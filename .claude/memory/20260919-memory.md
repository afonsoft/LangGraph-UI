## Decisions

- MCP v2: pacotes já estavam em 2.2.0 — o trabalho foi de *modo de transporte*,
  não de upgrade de pacote. Híbrido escolhido para não quebrar clients legados
  (initialize/SSE) nem a infra de sessão (registry, monitor, list_changed push).
- `SessionCallGate`: calls sem sessão ganharam bucket dedicado com o mesmo
  limite (8) — antes `GateFor(null)` retornava null → **unbounded** (gap real).
- Release pipeline: 3 fixes cirúrgicos em vez de redesign (SPEC pedia mínimo).
- Deploy prod neste host é sempre `docker compose up -d --build` (compose +
  override + .env) — `install.sh --docker` não monta volumes do override.
- Owner pediu commits diretos na main p/ docs de SPECs — bypass registrado;
  features/fixes continuam via PR.

## Mistakes / lessons

- **Wire contract MCP 2026-07-28** (descoberto por tentativa/erro nos testes):
  exige header `MCP-Protocol-Version` + `Mcp-Method` + `Mcp-Name` (tools/call) +
  `params._meta["io.modelcontextprotocol/protocolVersion"]` +
  `params._meta["io.modelcontextprotocol/clientCapabilities"]`. `ping` NÃO
  existe em 2026-07-28 (use `tools/list` p/ smoke).
- **NU1403**: MS republicou `Microsoft.NET.ILLink.Tasks.10.0.12` com hash
  diferente → locked-mode restore quebra CI até `dotnet restore
  --force-evaluate` regenerar o lockfile. Branches que tocam packages.lock.json
  "herdam" o fix.
- **build-push-action + `cache-to: type=gha`** exige `setup-buildx-action`;
  sem ele o driver docker falha com "Cache export is not supported".
- **action-gh-release + `files: dir/**`** faz upload de CADA arquivo como asset
  (222+ uploads → secondary rate limit). Sempre empacotar em archives.
- Shell quoting: sed/replace com backticks em Markdown falha silenciosamente —
  usar quoting seguro e verificar o resultado.
- `install.sh --docker --data-dir` novo precisa ser writable pelo uid 1654
  (warn do script é real — SQLite falha com "unable to open database file").
- `gh run rerun --failed` reusa artifacts dos jobs que passaram — útil p/
  rate-limit transitório, mas o root cause (500 uploads) precisava do fix de
  archives.
- Re-dispatch de workflow_dispatch roda o YAML do ref escolhido (main) —
  consertar o workflow em main e re-dispatch com version=X.Y.Z repara releases
  antigas sem re-tag.
